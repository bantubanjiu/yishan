# 移山前端交互功能入口梳理与优化分析

> 版本：v0.1  
> 日期：2026-05-14  
> 范围：`extension/` 浏览器扩展前端、前台注入交互、Background 消息分发，以及与交互入口直接相关的 Native Host 请求。  
> 目的：为后续“优化前端界面”提供当前交互入口清单、用户使用说明、实现依据与优化方向。

## 1. 项目当前前端形态

“移山”不是传统 Web App，而是一个 Chrome/Edge Manifest V3 扩展。用户可见的前端入口由以下几层组成：

1. **扩展图标 Popup**：点击浏览器工具栏中的“移山”图标打开，提供高频操作和轻量设置。
2. **扩展选项页 Options**：从扩展详情页/扩展管理页打开，偏向配置管理。
3. **网页右键菜单 Context Menu**：在页面、选区、图片等上下文中出现，负责最贴近内容的保存动作。
4. **浏览器快捷键 Commands**：通过 Chrome 扩展快捷键触发保存全部标签或框选截图。
5. **页面注入交互**：包括框选截图遮罩、长按触发键拖选保存文本等直接覆盖在网页上的交互。
6. **系统/Obsidian 打开入口**：通过 Native Host 请求打开今天 Inbox，目前 UI 中只暴露“打开今天 Inbox”。

核心代码依据：

- `extension/manifest.json`：声明 Popup、Options、Commands、权限与后台入口。
- `extension/popup.html` / `extension/popup.js`：Popup UI 与按钮事件。
- `extension/options.html` / `extension/options.js`：设置页 UI 与按钮事件。
- `extension/context-menu.js`：右键菜单项创建与 capture message 构造。
- `extension/background.js`：安装、启动、标签切换、右键、快捷键、Popup runtime message 的总分发。
- `extension/gesture.js`：长按触发键后拖选保存文本的页面注入逻辑。
- `extension/screenshot.js`：框选截图/当前视口截图的页面注入和裁剪逻辑。
- `src/host/host-request.ts`：配置读写、文件夹选择、打开路径、批量保存等 Native Host 请求处理。

## 3. 用户使用说明

### 3.1 第一次使用：完成 Vault 配置

1. 点击浏览器工具栏中的“移山”扩展图标，打开 Popup。
2. 在“保存位置”区域填写 **Vault 路径**，或点击“选择”打开系统文件夹选择器。
3. 选择 Obsidian Vault 根目录，例如 `D:\Obsidian\Vault`。
4. 根据需要设置：
   - **选区快捷键**：可选 `Alt`、`Ctrl`、`Shift`、`Meta / Command`。
   - **选中文本保存模式**：
     - `安全纯文本`：优先保证稳定，不破坏日记结构。
     - `富 Markdown`：尽量保留标题、列表、链接、引用、代码块、图片等结构，失败时回退纯文本。
   - **启用长按拖选自动保存**：默认关闭，开启后可用触发键 + 鼠标拖选自动保存。
5. 点击“保存设置”。
6. Popup 底部状态显示“设置已保存。”即完成配置。

同样也可以从扩展详情页打开“移山设置”页面完成上述配置。

### 3.2 使用 Popup 高频操作

#### 保存全部标签

适用场景：想把当前窗口里的网页链接快速保存为稍后阅读列表。

操作步骤：

1. 打开要保存的浏览器窗口。
2. 点击“移山”扩展图标。
3. 点击“保存全部标签”。
4. 插件会保存当前窗口中所有普通 `http/https/file` 标签，跳过 `chrome://` 等浏览器内部页。
5. 保存结果写入当天 Inbox，并在 Popup 状态区显示保存数量或失败数量。

#### 框选截图

适用场景：只保存页面局部内容，如图表、卡片、评论片段。

操作步骤：

1. 点击“移山”扩展图标。
2. 点击“框选截图”。
3. 页面上出现截图选择交互。
4. 拖拽选择需要保存的区域。
5. 松开鼠标后，截图保存为附件，并在当天 Inbox 对应页面分组下插入 Obsidian 附件嵌入。
6. 若想取消，按 `Esc`。

#### 整屏截图

适用场景：保存当前可见视口，不需要手动框选。

操作步骤：

1. 点击“移山”扩展图标。
2. 点击“整屏截图”。
3. 当前可见区域会直接保存为截图附件，并写入当天 Inbox。

注意：当前“整屏截图”指当前视口，不是滚动长截图。

#### 打开今天 Inbox

适用场景：保存后立刻查看今天写入的 Obsidian 日记。

操作步骤：

1. 点击“移山”扩展图标。
2. 点击“打开今天 Inbox”。
3. Native Host 会解析 Vault 下的 `Inbox/YYYY-MM-DD.md`，并通过 Obsidian URI 打开。

当前限制：如果当天 Inbox 文件还不存在，会返回“路径不存在”。

#### 打开 Chrome 快捷键设置

适用场景：默认快捷键冲突，或希望改成自己的快捷键。

操作步骤：

1. 点击“移山”扩展图标。
2. 点击“打开 Chrome 快捷键设置”。
3. 在 Chrome/Edge 扩展快捷键页面修改“移山”的两个命令快捷键。

### 3.3 使用右键菜单保存内容

#### 保存当前页面剪藏到 Obsidian

适用场景：保存网页正文为一篇单独 Markdown 文档。

操作步骤：

1. 在网页空白处右键。
2. 点击“保存当前页面剪藏到 Obsidian”。
3. 扩展会优先提取 `article`、`main`、`[role=main]` 等正文区域；如果找不到，则回退到页面主体。
4. 脚本、样式、导航、表单、按钮、输入框等噪声节点会被移除。
5. 提取标题、段落、标题层级、链接、列表、代码块、引用、表格和图片。
6. Native Host 会在 Inbox 目录下生成单独 Markdown 文档；页面图片会尽量下载到附件目录并改写为 Obsidian 本地嵌入。

与“保存全部标签”的区别：页面剪藏保存正文内容，生成单独文档；保存全部标签只保存链接，写入当天 Inbox。

#### 保存选中文本到 Obsidian

适用场景：只摘录页面中的一段文字、代码或说明。

操作步骤：

1. 在网页中选中文本。
2. 右键选区。
3. 点击“保存选中文本到 Obsidian”。
4. 扩展根据当前“选中文本保存模式”决定保存纯文本或富 Markdown。
5. 内容写入当天 Inbox，并按同一天同一网址归入同一个页面分组。

补充：在 `input`、`textarea`、可编辑区域中右键选区也支持保存。

#### 保存图片到 Obsidian

适用场景：保存网页中的单张图片。

操作步骤：

1. 在图片上右键。
2. 点击“保存图片到 Obsidian”。
3. Native Host 下载图片、校验类型和大小，然后写入附件目录。
4. 当天 Inbox 中只写入 Obsidian 附件嵌入；如果下载失败，会记录失败原因，不写入原始图片 URL。

注意：远程图片存在 10 秒超时、20MB 上限和图片类型校验。

#### 框选截图保存到 Obsidian

适用场景：右键路径下直接进入截图选区，而不用先打开 Popup。

操作步骤：

1. 在页面、选区、图片或编辑区域右键。
2. 点击“框选截图保存到 Obsidian”。
3. 页面顶部出现提示“拖拽选择截图区域，按 Esc 取消”。
4. 拖拽选择区域并松开鼠标。
5. 截图保存到附件目录，并写入当天 Inbox 对应页面分组。

### 3.4 使用快捷键

默认快捷键由 `manifest.json` 声明，可在 `chrome://extensions/shortcuts` 修改：

| 快捷键 | 功能 | 使用说明 |
| --- | --- | --- |
| `Alt+Shift+S` | 保存当前窗口标签 | 在任意页面按下后，保存当前窗口全部普通 `http/https/file` 标签链接。 |
| `Alt+Shift+X` | 框选截图 | 按下后进入框选截图模式，拖拽选区保存，`Esc` 取消。 |

如果快捷键无效，优先检查：

1. 浏览器快捷键页面是否被其他扩展/系统占用。
2. 当前页面是否是浏览器内部页，例如 `chrome://`，这类页面不可注入脚本。
3. 扩展是否已完成 Native Host 安装和 Vault 配置。

### 3.5 使用长按拖选自动保存

适用场景：高频摘录网页文本，希望减少“选中 → 右键 → 点击菜单”的步骤。

开启步骤：

1. 打开 Popup 或 Options。
2. 勾选“启用长按拖选自动保存”。
3. 选择触发键，默认为 `Alt`。
4. 点击“保存设置”。

使用步骤：

1. 在普通网页上按住触发键约 250ms。
2. 鼠标左键拖选文本。
3. 页面会出现蓝色选区框。
4. 松开鼠标后，如果检测到选中文本，会自动保存到 Obsidian。
5. 按 `Esc` 可取消当前触发状态。

当前限制：

- 仅在 `http:`、`https:`、`file:` 页面注入；浏览器内部页不可用。
- 可编辑区域会被跳过，避免干扰输入。
- 某些站点如果禁止脚本注入或选区行为特殊，可能不可用。

## 4. 当前信息架构分析

### 4.1 功能按“采集类型”分散在多个入口

当前能力可归纳为五类采集：

1. 页面正文剪藏：右键菜单。
2. 文本摘录：右键菜单、长按拖选。
3. 图片保存：右键菜单。
4. 截图保存：Popup、右键菜单、快捷键。
5. 多标签链接保存：Popup、快捷键。

这说明系统能力已经比较完整，但 UI 暴露方式偏“入口驱动”：同一功能在不同入口复用，不同功能又分布在 Popup、右键和快捷键里。用户如果只打开 Popup，会看不到“保存页面剪藏”“保存图片”“保存选中文本”的明确入口；如果只用右键，会看不到“保存全部标签”“整屏截图”“打开 Inbox”和设置能力。

### 4.2 Popup 当前更像“快捷操作 + 设置混合页”

Popup 首屏包含：

- 高频动作：保存全部标签、框选截图、整屏截图。
- 设置项：Vault 路径、触发键、保存模式、拖选开关。
- 路径动作：打开今天 Inbox。
- 系统入口：打开 Chrome 快捷键设置。

优点：所有关键操作集中，配置成本低。

问题：采集动作和配置项混在一个短 Popup 中，用户第一次打开时可能不清楚“我现在能保存什么”。同时，README 中提到过附件目录、Vault 根目录、配置文件等路径按钮，但当前 Popup HTML 只保留了“打开今天 Inbox”，UI 与历史描述存在差异。

### 4.3 Options 与 Popup 设置重复

Options 页面提供 Vault 路径、选区快捷键、选中文本保存模式、拖选开关、保存/读取/快捷键入口。Popup 也提供几乎同样的设置项。

优点：用户无需进入 Options 就能完成配置。

问题：重复 UI 会增加维护成本；如果后续增加 Inbox 目录、附件目录、剪藏策略等高级设置，需要决定是否同时放在 Popup 和 Options。

### 4.4 反馈机制以状态文本和通知为主

当前反馈来源：

- Popup/Options 底部 `role=status` 文本。
- 保存类动作触发 Chrome 通知。
- 右键和快捷键动作触发 Chrome 通知。
- 截图模式页面上有临时遮罩提示。
- 拖选保存有蓝色框，但没有保存中/成功的页面内提示，成功依赖通知。

优点：实现轻量，不打断用户。

问题：不同入口反馈不完全一致；例如 Popup 截图有状态和通知，右键截图主要是通知，拖选自动保存主要靠通知。后续做界面优化时可以统一反馈语言、状态层级和错误指引。

## 5. 当前交互链路分析

### 5.1 Popup 链路

```text
用户点击 Popup 按钮
  -> popup.js 发送 chrome.runtime.sendMessage
  -> background.js handleRuntimeMessage
  -> 执行扩展侧能力或转发 Native Host
  -> Native Host 写入配置/文件/附件
  -> Popup 状态区 + 可选通知反馈
```

典型消息类型：

- `save-current-window`
- `capture-screenshot`
- `capture-viewport-screenshot`
- `get-config`
- `set-config`
- `pick-folder`
- `open-path`
- `open-shortcuts`

Popup 还保留了部分 fallback：如果 runtime message 不可用，会直接调用 Native Messaging 或本地 Chrome API。

### 5.2 右键菜单链路

```text
安装扩展/更新扩展
  -> background.js onInstalled
  -> context-menu.js createContextMenus
用户右键点击菜单
  -> background.js chrome.contextMenus.onClicked
  -> context-menu.js buildCaptureMessage
  -> native-client.js saveCapture
  -> Native Host writeCaptureToVault
  -> Chrome 通知反馈
```

不同菜单项构造不同 `CaptureMessage`：

- 页面剪藏：`type: "page"`
- 选中文本：`type: "selection"`
- 图片：`type: "image"`
- 截图：`type: "image"`，但 `imageUrl` 是截图 data URL。

### 5.3 快捷键链路

```text
用户按快捷键
  -> commands.js chrome.commands.onCommand
  -> 保存全部标签或框选截图
  -> Native Host 写入
  -> Chrome 通知反馈
```

两个命令均声明在 `manifest.json` 中，用户可在浏览器快捷键管理页重绑定。

### 5.4 长按拖选链路

```text
保存配置/标签切换/页面刷新/窗口聚焦
  -> background.js 同步 gesture 状态
  -> gesture.js 按需注入/卸载页面脚本
用户长按触发键 + 拖选文本
  -> 页面脚本 sendMessage: save-selection-from-gesture
  -> background.js 读取保存模式并补充 Markdown
  -> Native Host 写入 selection
  -> Chrome 通知反馈
```

该链路依赖标签生命周期同步：安装、启动、标签激活、页面 loading/complete/url 变化、窗口重新聚焦都会尝试同步注入状态。

### 5.5 Native Host 写入结果

交互入口最终落到四类捕获消息：

| 类型 | 来源入口 | 写入位置 |
| --- | --- | --- |
| `url` | 保存全部标签/快捷键 | 当天 Inbox，按同日同 URL 分组 |
| `page` | 保存当前页面剪藏 | Inbox 目录下单独 Markdown 文档 |
| `selection` | 右键保存选中文本/长按拖选 | 当天 Inbox，按同日同 URL 分组 |
| `image` | 保存图片/截图/整屏截图 | 附件目录 + 当天 Inbox 分组嵌入 |

## 6. 前端界面优化建议

### P0：先建立“功能地图”式 Popup 信息架构

目标：用户打开 Popup 后能立刻知道“移山能做什么”。

建议把 Popup 分为三块：

1. **立即采集**
   - 保存页面剪藏（当前只在右键出现，可考虑加入 Popup）
   - 保存全部标签
   - 框选截图
   - 整屏截图
2. **摘录方式**
   - 提示：选中文本后右键保存
   - 拖选自动保存开关 + 当前触发键
   - 保存模式：安全纯文本 / 富 Markdown
3. **保存位置与工具**
   - Vault 路径摘要
   - 打开今天 Inbox
   - 设置 / 快捷键

这样能把“功能入口”从代码中的分散状态，整理成用户可理解的采集地图。

### P0：补齐用户看不到但已存在的重要入口说明

当前 Popup 没有直接告诉用户：

- 页面剪藏在“网页空白处右键”。
- 保存选中文本在“选中文本后右键”。
- 保存图片在“图片上右键”。
- 长按拖选需要先启用，并且长按约 250ms 后拖选。
- `Alt+Shift+S`、`Alt+Shift+X` 可以在快捷键页修改。

建议在 Popup 添加一块简短“怎么用”或“更多入口”：

```text
更多保存方式：
- 页面空白处右键：保存页面剪藏
- 选中文本右键：保存摘录
- 图片右键：保存图片
- Alt+Shift+S：保存全部标签
- Alt+Shift+X：框选截图
```

### P1：区分“高频采集”和“设置”

当前设置项占据 Popup 较大空间。建议：

- Popup 只保留 Vault 路径摘要、拖选开关、保存模式这些高频/关键设置。
- 高级配置放到 Options，例如 Inbox 目录、附件目录、剪藏策略、图片下载策略、是否自动打开保存结果。
- Popup 中提供“完整设置”入口，而不是把所有配置都平铺。

### P1：统一保存反馈

建议定义统一反馈模板：

| 场景 | 建议反馈 |
| --- | --- |
| 保存成功 | “已保存：{类型} → {目标位置}” |
| 部分成功 | “已保存 {saved}/{attempted}，失败 {failed} 个，可查看详情” |
| 用户取消 | “已取消，不会保存内容” |
| 配置缺失 | “请先设置 Obsidian Vault 路径” + “去设置”按钮 |
| 当前页面不可操作 | “浏览器内部页无法注入，请在普通网页使用” |
| 今天 Inbox 不存在 | “今天 Inbox 还不存在，先保存一条内容后再打开” 或提供创建选项 |

### P1：增加入口状态可见性

建议在 Popup 显示当前状态：

- Vault：已配置 / 未配置。
- 拖选保存：开启 / 关闭；当前触发键。
- 快捷键：默认值提示 + “可修改”。
- 当前页面：是否普通页面、是否支持截图/剪藏/拖选。

这样可以减少“点击后才报错”的体验。

### P2：统一 Popup 与 Options 的职责

建议定位：

- **Popup = 快捷采集控制台**：以操作为主，只保留必要设置。
- **Options = 完整设置中心**：管理路径、保存模式、快捷键说明、高级项、诊断信息。

后续如果增加 Inbox 目录、附件目录、页面剪藏规则，优先放在 Options；Popup 只显示摘要和入口。

### P2：增加帮助/文档入口

可以在 Popup 或 Options 增加“使用说明”折叠区，内容来自本文档的精简版。对于本地工具，用户常见问题主要是：

- 为什么内部页不能保存？
- 为什么 file:// 不可用？需要开启“允许访问文件网址”。
- 为什么打开今天 Inbox 报路径不存在？
- 截图是不是滚动长截图？当前不是。
- 页面剪藏和保存全部标签有什么区别？

### P2：优化截图和拖选的页面内提示

当前截图遮罩提示比较明确；拖选保存只有蓝色框。建议：

- 拖选 armed 后显示轻量提示：“松开后保存选区，Esc 取消”。
- 保存中显示短暂 toast：“正在保存到 Obsidian...”。
- 成功/失败用页面内 toast + Chrome 通知二选一或保持一致。

### P3：补齐或修正文档与 UI 差异

README 中提到 Popup 可打开今天 Inbox、附件目录、Vault 根目录和配置文件，但当前 `popup.html` 只存在“打开今天 Inbox”。建议二选一：

1. 如果产品仍计划支持多个路径打开入口：补回 UI 和 Native Host target。
2. 如果当前只保留 Inbox：更新 README，避免用户按旧说明寻找不存在入口。

Native Host 当前 `open-path` 只允许 `today-inbox`，因此补回多个路径按钮还需要扩展 `OpenPathRequest` 和 `resolveOpenPathTarget`。

## 7. 建议的后续设计方向

### 方案 A：轻量整理，不大改结构

适合短期快速优化。

- Popup 顶部加“当前 Vault 状态”。
- 快捷操作按钮文案更清晰：
  - “保存全部标签” → “保存当前窗口标签”
  - “整屏截图” → “保存当前视口”
- 增加“更多保存方式”说明区，解释右键菜单和快捷键。
- 把设置区标题从“保存位置”调整为“保存设置”。
- Options 增加完整使用说明和常见问题。

### 方案 B：重新设计 Popup 为采集控制台

适合中期 UI 优化。

- 主操作区：页面剪藏 / 当前窗口标签 / 框选截图 / 当前视口。
- 摘录区：选中文本右键提示、拖选开关、保存模式。
- 位置区：Vault 状态、打开今天 Inbox、完整设置。
- 底部：快捷键提示和状态反馈。

### 方案 C：引入引导式首次配置

适合提升新用户转化。

- 未配置 Vault 时，Popup 首屏只显示配置引导。
- 配置完成后切换为正常采集控制台。
- 配置错误时提供明确修复动作。

## 8. 入口优先级建议

| 优先级 | 入口/能力 | 原因 |
| --- | --- | --- |
| P0 | Vault 配置状态与保存设置 | 没有配置则所有保存能力不可用。 |
| P0 | 保存页面剪藏入口说明 | 这是核心能力，但当前 Popup 不可见。 |
| P0 | 保存选中文本/图片的右键说明 | 高频能力隐藏在上下文菜单中，需要教育用户。 |
| P0 | 截图入口文案统一 | Popup、右键、快捷键都有截图，需降低理解成本。 |
| P1 | 快捷键说明和重绑定入口 | 已实现能力，应让用户知道。 |
| P1 | 打开今天 Inbox 的失败指引 | 当前文件不存在会直接报错，体验不完整。 |
| P1 | Popup/Options 职责拆分 | 降低后续维护和 UI 拥挤。 |
| P2 | 页面内 toast | 改善拖选/截图的闭环反馈。 |
| P2 | 多路径打开入口 | README 曾提及，但代码当前只支持今天 Inbox。 |

## 9. 证据摘录

- `extension/manifest.json` 声明 `action.default_popup`、`options_page` 和两个命令：`quick-save-current-window`、`capture-screenshot-area`。
- `extension/popup.html` 暴露保存全部标签、框选截图、整屏截图、Vault 路径、选择、选区快捷键、保存模式、拖选开关、打开今天 Inbox、保存设置、打开 Chrome 快捷键设置。
- `extension/options.html` 暴露 Vault 路径、选择文件夹、选区快捷键、保存模式、拖选开关、保存设置、读取当前设置、打开 Chrome 快捷键设置。
- `extension/context-menu.js` 创建四个右键菜单：框选截图、保存当前页面剪藏、保存选中文本、保存图片。
- `extension/commands.js` 监听两个快捷键命令：框选截图、保存当前窗口标签。
- `extension/background.js` 负责右键点击、runtime message、标签生命周期同步、快捷键注册。
- `extension/gesture.js` 只在 `http/https/file` 页面注入拖选脚本，且依赖 `selectionGestureEnabled`。
- `extension/screenshot.js` 为框选截图注入页面遮罩，支持 `Esc` 取消；当前视口截图不需要框选。
- `src/host/host-request.ts` 的 `open-path` 当前只允许 `today-inbox`。

## 10. 结论

当前项目已经具备完整的本地网页采集能力，但前端界面的主要问题不是能力缺失，而是**入口分散、功能发现成本高、Popup 同时承担操作和设置两种职责**。后续优化建议先做信息架构整理：让 Popup 成为“采集控制台”，让 Options 成为“完整设置中心”，并通过“更多保存方式/快捷键说明/状态提示”把右键菜单、快捷键和长按拖选这些隐藏入口显性化。
