# 前端设计协同评审更新报告

> 版本：v1.0  
> 日期：2026-05-14  
> 范围：`extension/` 前端交互入口、Popup / Options 信息架构、右键菜单、截图、拖选保存、快捷键与反馈闭环  
> 目的：合流三种评审视角，形成可执行的前端界面优化方向

## 1. 一句话结论

当前问题不是“功能不够”，而是**入口过散、职责混杂、主路径不够明确**。  
真正要优化的不是按钮皮肤，而是：**把浏览器里的有用内容，一步送进今天的 Obsidian。**

---

## 2. 三方评审结论

### 2.1 马斯克视角

核心判断：

- 入口白痴指数过高：底层最终只有 `url / page / selection / image` 四类捕获结果，但 UI 暴露成 Popup、右键、快捷键、长按拖选、Options 多套入口。
- Popup 现在同时承担“采集控制台 + 设置页”，职责冲突。
- 页面剪藏是第一性原理能力，但在 Popup 中不可见，这是最大信息架构断点。
- 长按拖选自动保存是高复杂度链路，应被审问是否真是高频能力。
- 反馈闭环不统一，用户不知道系统在哪一步。

建议：

- 砍掉重复入口，合并截图入口，保留右键上下文动作。
- Popup 主动作应前移到“保存当前页面”。
- 长按拖选默认隐藏或降级为高级功能。
- 反馈统一为：保存中 / 成功 / 部分失败 / 配置缺失 / 取消。

### 2.2 乔布斯视角

核心判断：

- Popup 没有一句话讲清“移山是什么”。
- 第一主按钮选错了：不应把“保存全部标签”放在最高权重，而应突出当前页面/当前内容。
- Popup 同时放采集动作与设置项，缺乏聚焦。
- 截图有较好的闭环提示，但拖选保存还不够“让人安心”。
- Popup 与 Options 复制了同一套设置逻辑，未来会导致体验分叉。

建议：

- 先做减法，再谈美化。
- 让 Popup 成为“采集遥控器”，Options 成为“设置与诊断中心”。
- 页面剪藏应成为主入口，而不是只藏在右键菜单里。
- 文案去技术化，成功反馈统一成用户语言，不要暴露 Native Host 细节。

### 2.3 Superpowers / UI/UX 视角

核心判断：

- 当前 UI 已有不错的视觉底子，但缺少信息层级与渐进披露。
- Accessibility、键盘/状态反馈、aria-live、触达尺寸、错误恢复不能缺。
- Popup/Options 的重复字段需要收敛，否则维护成本和一致性风险会持续上升。
- 入口说明可以补，但不能替代正确的信息架构。

建议：

- Popup = 快捷采集控制台。
- Options = 完整设置中心。
- 网页内交互 = 当下反馈闭环。
- 先瘦身入口，再补说明，再补高级状态和帮助。

## 3. 互评结果（judge）

| 评审 A | 评审 B | Judge |
| --- | --- | --- |
| 马斯克视角 | 乔布斯视角 | **高度一致**：都要求先删复杂度、突出主入口。差异在于马斯克更强调第一性原理和自动化边界，乔布斯更强调一句话定义和视觉层级。 |
| 马斯克视角 | Superpowers / UX | **部分一致**：都赞成统一反馈闭环，但 UX 进一步要求可访问性、键盘可达性、错误恢复，不能只做“更快更自动”。 |
| 乔布斯视角 | Superpowers / UX | **一致性高**：都支持 Popup / Options 分工、渐进披露、状态清晰；UX 负责把这种清晰做成可验证规范。 |

### 互相给建议的结论

- **马斯克对乔布斯**：赞成主入口聚焦，但反对先做风格化重设计；先删复杂度，再谈审美。
- **乔布斯对马斯克**：赞成入口重排，但反对在反馈不闭环前继续叠加自动化。
- **UX 对两者**：赞成方向，但要求把 accessibility、状态文案、取消路径、按钮可达性写成可执行标准。

## 4. 合流后的统一判断

### 4.1 当前 UI 的根问题

1. **主路径不明确**  
   用户打开 Popup 后，第一眼看到的是“保存全部标签”，而不是“保存当前页面”。

2. **职责混杂**  
   Popup 既像控制台，又像设置页。

3. **入口分散**  
   页面剪藏、选中文本、图片、截图、窗口标签分散在不同入口里，学习成本高。

4. **反馈不统一**  
   同样是“保存”，不同入口的提示方式不同，用户不能稳定判断是否完成。

5. **重复实现**  
   Popup 与 Options 重复配置字段和逻辑，长期会造成文案和行为漂移。

### 4.2 最优信息架构

- **Popup**：只负责“快速采集 + 状态摘要”
  - 保存当前页面
  - 保存当前窗口标签
  - 截图（框选 / 当前视口）
  - Vault 状态、今天 Inbox、完整设置入口

- **Options**：只负责“完整设置 + 诊断”
  - Vault 路径
  - 保存模式
  - 拖选开关
  - 触发键
  - 快捷键说明
  - 故障排查

- **右键菜单**：保留上下文相关动作
  - 页面剪藏
  - 选中文本
  - 图片
  - 截图

- **网页内交互**：统一反馈语言
  - 保存中
  - 成功
  - 部分失败
  - 已取消
  - 配置缺失

---

## 5. 优先级建议

### P0

- 把“保存当前页面剪藏”提升到 Popup 主入口
- Popup 与 Options 职责拆分
- 统一所有入口的保存反馈
- 明确 Vault 是否已配置

### P1

- 合并截图入口，统一成一个“截图”能力
- 降级或隐藏长按拖选自动保存
- 去技术化文案
- 压缩 Popup 内设置项，只保留摘要

### P2

- 增加帮助 / FAQ 的渐进披露
- 补齐拖选保存的页面内提示
- 进一步统一状态语义与错误恢复路径

---

## 6. 最终结论

这次协同 review 的共识非常清晰：

> **先删复杂度，再定主入口；先统一反馈，再谈美化。**

如果只做一件事，应该是：  
**把 Popup 从“混合型小面板”改成真正的“采集控制台”，并把“保存当前页面”放到第一主动作。**
